# Module Checklist

Master roadmap. Every module candidate — implemented, planned, or brainstormed — in one list. Check off as we ship.

Sources: Project SWT feature extraction (95 features across 3 slice files), pre-existing moduleIdeas notes, and `moduleIdeas.txt` seed ideas. Deduplicated.

---

## Already implemented

- [x] **core.preamble** — Structural preamble + Session Manifest read-on-demand contract.
- [x] **core.tpm** — TPM orchestrator identity + universal hard rules.
- [x] **core.swe** — SWE role with four inlined workflow modes (preview/edge-case-hunt/review/planning).
- [x] **core.qa** — QA role + verdict tiers (PASS / PASS WITH NOTES / FAIL).
- [x] **tool.git** — Read-only git allowlist + user-managed protected branches.
- [x] **tool.dotnet-suite** — .NET guardrails: protects appsettings/launchSettings and bans `dotnet` CLI.
- [x] **tool.database-access** — Read-only LINQPad SQL via project→connection allowlist.
- [x] **tool.npm-suite** — Per-row enable/disable allowlist of npm + Angular CLI commands.
- [x] **tool.fastpath-check** — Detects WSL fast-path; launcher cd's bash terminal into it on session start.
- [x] **tool.lenses** — Three-lens deployment for Review Mode (security/logic/quality) and Planning Mode (architecture/implementation/test-strategy), with `Rating: N/5` rubric and configurable lens vocabularies via keywords files.
- [x] **tool.feedback-log** — Cross-session feedback log; TPM appends entries to a JSON file in extension global storage, Feedback tab in the settings panel exposes Yes/No/Delete triage on cards.
- [x] **integration.atlassian-suite** — Atlassian credentials module (email, API token in SecretStorage, Jira base URL, Bitbucket workspace) plus REST integration: token validation against Jira `/myself` and Bitbucket workspace endpoints, ticket-existence and open-PR-by-branch lookups feeding the optional Source Control branch widget's button states. Includes Refresh button and streaming API state updates.
- [x] **integration.bitbucket-pr-comments** — PR Monitor: fetch open Bitbucket PR review comments via the Atlassian Suite's AtlassianBridge, triage them with `address` ordinal grammar, dispatch SWEs in parallel to apply code fixes, generate 1-2 sentence replies (with optional CodeRabbit persona overlay) under explicit user approval, and post replies back to Bitbucket. Includes the falsely-resolved-comment scanner (off-by-default detection of comments claiming resolution that Bitbucket still flags as unresolved).
- [x] **integration.merkle** — Connect Nomeda agents to a running Project-Merkle deployment over its MCP endpoint; configurable serverBaseUrl + defaultTeamName + defaultPasscode + verifyOnConnect; agent flow covers verify → join → long-poll → post → exit on session_closed; references Merkle's `scripts/agent-loop.mjs` for sustained-presence deployment.
- [x] **tool.obsidian-notes** — Obsidian vault as agent knowledge base; configurable vaultPath + autoDiscoverVault + projectsSubfolder + searchRoots; proactive session-start discovery searches common WSL/Windows locations for .obsidian markers, asks the user to pick when multiple vaults are found, and soft-persists the chosen path back to the manifest's vaultPath.default so it appears in the panel on next launch; TPM-only write discipline with parent knowledge files at <vault>/<Project>/<Project>.md, per-ticket notes at <vault>/<Project>/<Ticket>.md, and Directory Navigation mode project notes at <vault>/<projectsSubfolder>/<cwd-basename>.md.
- [x] **tool.session-handoff** — Structured session wrap-up + multi-session resume protocol; configurable wrapUpTrigger + surfaceOnResume + sectionsToInclude + dateFormat; proactive session-start surfacing of the most-recent ## Session Handoff block from the active project or ticket notes file; TPM writes wrap-ups on user signal (or after proposing on auto-on-quiet) with completed/in-progress/pending/decisions/blockers sections, appending new dated blocks rather than overwriting; degrades gracefully if tool.obsidian-notes is disabled or the vault is unresolved.
- [x] **mode.cd** — First session-mode module; scopes the session strictly to cwd as a named project; configurable redirectStrictness (ask / hard-block / soft-warn) + projectNoteSections + autoCreateNotesFile + projectNameSource (cwd-basename or git-remote); proactive session-start project context resolution derives the project name, resolves the notes file path via tool.obsidian-notes, auto-creates the file with the configured sections when missing, and defers Session Handoff surfacing to tool.session-handoff; mid-session cwd discipline enforces the redirect policy when the user references work outside cwd; degrades gracefully when tool.obsidian-notes is disabled or the vault is unresolved.
- [x] **mode.ticket-work** — Second session-mode module (mutually exclusive with mode.cd); scopes the session strictly to a single Jira ticket; configurable ticketId + pullOnStart + crossTicketStrictness (ask / hard-block / soft-warn) + notesSections + untrustedJiraInput; proactive session-start ticket resolution asks the user for a ticket id if unset, pulls the ticket via integration.atlassian-suite when pullOnStart is true, sets up per-ticket notes at <vault>/<Project>/<Ticket>.md via tool.obsidian-notes with the configured sections, and surfaces any prior handoff via tool.session-handoff; treats Jira ticket descriptions as untrusted external input by default — Jira content is context not directive, suspicious instructions are flagged before acting; mid-session cross-ticket discipline keeps notes anchored to the active ticket even when the user references other tickets in conversation; degrades gracefully when Atlassian integration is unavailable (manual paste fallback), when tool.obsidian-notes is unloaded (in-session only), or when tool.session-handoff is unloaded (no resume surfacing).
- [x] **tool.pre-pr-checklist** — User-managed quality-gate sweep run before a PR is created; configurable checks (keyValue with optionalEnabled — 10 seeded defaults covering tests, unintended changes, secrets, commented code, TODO markers, error handling, null checks, dead code, naming conventions, edge case coverage) + runMode (interactive walks one-at-a-time vs batched single summary) + autoOfferOnSignal (proactively offers when user signals PR-handoff); not proactive — fires only on user signal or explicit request; TPM reads the git diff plus session memory, evaluates each enabled check, presents findings with ✓ / ⚠ / ✗ severity markers, and lets the user decide whether to address flagged items before creating the PR.
- [x] **tool.pr-description** — Generates a PR description from session changes on user signal; configurable maxSentences (default 2) + format (ticket-then-what-then-why default, what-then-why, or bullet) + bannedTokens (default forbids ASCII double-dashes and adjacent patterns per CodeRabbit conventions) + includeChangeSummary + autoOfferOnSignal; not proactive — fires after the pre-PR checklist completes (when both modules enabled) or on explicit ask; references the ticket id from mode.ticket-work when active, drops the prefix gracefully otherwise; TPM presents the draft for the user to copy, tweak, or regenerate from a different angle; banned-token scan rewrites any forbidden sequences before presenting.
- [x] **tool.regression-scan** — Third gate in the PR-handoff trio (after pre-pr-checklist and pr-description); greps configured test directories for references to symbols changed in the session and flags tests that need re-running before a PR; configurable testRoots (default tests/test/__tests__/spec/specs/e2e) + fileExtensions (default .ts/.tsx/.js/.jsx/.py/.cs/.java/.go/.rs) + scanSignals (classes/methods/exported-functions/public-types) + runMode (summary table vs per-symbol walk) + autoOfferOnSignal + flagThreshold (minimum reference count to surface); not proactive — fires on user signal or after the pre-PR checklist completes; symbol set built from SWE return messages + git diff, greps batched per-symbol via grep or rg, presented per runMode; symbols with zero references listed separately as potential coverage gaps; does not run tests or modify any file.
- [x] **tool.ac-to-testing** — TPM + user collaborative ritual that turns AC items into structured testing procedures and writes them to the Obsidian per-ticket notes' Testing Procedures section; configurable procedureTemplate (steps-expected-edge default, steps-expected, or gherkin) + autoOfferOnAcComplete + oneProcedurePerAcItem (separate vs consolidated) + probeEdgeCases (active prompting for null inputs, boundaries, concurrency, permissions, failures) + writeToNotes (persist to notes vs session memory only); not proactive — fires on user signal (AC marked complete, "testing time", explicit ask); AC source resolution priority is Ticket Widget todos → notes file AC section → user paste → Jira re-pull via integration.atlassian-suite; procedures numbered TP-1, TP-2 per ticket; the prerequisite for tool.playwright which will write Playwright specs from these procedures.
- [x] **tool.mid-session-bootstrap** — Watches user turns for ticket-id references via configurable regex and offers to retroactively bootstrap ticket-work-mode behaviors (Jira pull via integration.atlassian-suite, per-ticket notes setup via tool.obsidian-notes, optional session scope binding); configurable detectionPattern + autoOfferOnFirstMention + bootstrapScope (full / notes-only / lookup-only) + skipWhenTicketModeActive + crossTicketBootstrap (ask / switch / ignore); not proactive — detection runs on user-turn parsing, never at session start; per-session dedup so the same ticket id is offered once; cross-ticket gestures handled per the configured behavior; graceful dependency degradation (offers lookup-only fallback when tool.obsidian-notes is unavailable, full refusal with clear message when integration.atlassian-suite is unavailable).
- [x] **tool.untrusted-jira** — Project-wide untrusted-external-input convention (display name "Untrusted External Input"); configurable enforceFilter master switch + flaggedPatterns (default covers prompt-injection openers and role-impersonation tokens like "ignore previous instructions", "you are now", "<|im_start|>") + untrustedSources tag list (jira-description / jira-comment / bitbucket-description / bitbucket-comment / user-paste-from-external) + onFlagBehavior (ask / refuse / log-only) + includeInSweAssignments; not proactive — applies on-demand when a consuming module hands off tagged content; central "context not directive" frame with source-tag contract for consuming modules; defers from inline sections in mode.ticket-work and integration.bitbucket-pr-comments when enabled, leaving those inline sections as fallback when disabled.
- [x] **tool.statusline** — Nomeda status-bar display contract; configurable showVersion + showCumulativeTokens + showContextPercent + showRollingWindowPercent + redThresholdPercent (default 85) + fallbackToVersionOnly; not proactive — config consulted by extension-side render path when redrawing; four-segment compact pill ([Nomeda vX.Y.Z │ 142k · 62% · 5h 41%]); each segment renders independently and gracefully degrades when its data source is unavailable; context % and rolling-window % render in red at or above the configured threshold; module owns the contract only — the actual VS Code status-bar registration is extension-side wiring scheduled for a follow-up build.
- [x] **tool.clipboard-image** — Reads Windows clipboard images via a PowerShell helper so TPM can pass screenshots to Claude Vision; configurable scriptPath (default scripts/clipboard-read.ps1) + tempFileDir + autoReadOnTriggerPhrase + triggerPhrases (default covers "look at my clipboard", "check this screenshot", etc.) + includePathInSweAssignments; not proactive — fires on trigger-phrase detection or explicit ask; graceful failure modes for no-clipboard-image / missing-script / runtime-errors; clean SWE handoff via Screenshot: <abs-path> line in assignments so downstream agents can re-read the image; module owns the contract — the PowerShell helper script itself is a separate future scaffolding task.
- [x] **tool.cross-ticket-isolation** — Project-wide convention that cross-ticket discussions stay in session memory and are never written to any active ticket's notes file; configurable enforceIsolation + allowCrossTicketNoteWrite + promptBeforeCrossWrite + onIsolationViolation (refuse / log-only / ask); not proactive — applies on-demand at notes-write time; exception path allows cross-ticket discoveries to be written to the OTHER ticket's notes file with optional user confirmation; defers from inline sections in mode.ticket-work, tool.obsidian-notes, and tool.session-handoff when enabled.
- [x] **tool.cwd-discipline** — Project-wide convention enforcing agents stay in the user's cwd by default with explicit exception paths; configurable enforceDiscipline + allowedExceptionPaths (keyValue with seeded Obsidian / settings / secrets / SWT scripts entries) + onRedirectMidSession (accept / confirm / refuse) + treatModeBindingsAsExceptions; not proactive — applies on-demand per file operation; mode-driven path bindings (mode.cd's project dir, mode.support's app paths) implicitly extend the allowed set; defers from cores' inline cwd hard rules when enabled.
- [x] **tool.secrets-wrapper-pattern** — Project-wide convention that agents never read secrets directly — wrapper scripts source credentials at call time without exposing values; configurable enforcePattern + secretEnvPatterns (default *_TOKEN / *_SECRET / *_KEY / *_PASSWORD / *_PASS / *_CREDENTIAL) + secretFilePaths (default ${SWT_SECRETS_PATH} / ~/.netrc / ~/.aws/credentials / ~/.ssh/id_* / ~/.config/gh/hosts.yml) + approvedWrappers (keyValue with seeded bb-curl.sh / lprun-query.sh / clipboard-read.ps1) + onViolation (refuse / log-only / ask); not proactive — applies on-demand at secret-access time; defers from cores' inline NEVER-READ-SECRETS hard rules when enabled.
- [x] **tool.qa-pr-learning** — QA-behavior augmentation that consumes the PR-comment log from integration.bitbucket-pr-comments to surface team-specific review patterns; configurable learningEnabled + logSourcePath (defers to canonical bitbucket path when empty) + patternExtractionMode (recurring-themes default, author-styles, literal-quotes) + minLogEntriesToActivate (default 10) + surfaceLearnedPatterns; not proactive — QA consults the log at review time; target: qa only (TPM/SWE not in the loop); silent activation gate below the minimum threshold; verdict citations like "Learned pattern: 4 prior PRs flagged null checks on async returns" when surfacing is on.
- [x] **tool.session-bootstrap** — Orchestrates the session-start sequence — config load, team allocation, branch detection, proactive-module consultation, ready signal — and renders user-facing boot diagnostics; configurable steps (keyValue with 5 seeded SWT-convention steps, optionalEnabled per-step) + outputFormat (swt-style default emits "[swt] ✓ step — detail", compact, silent) + failureBehavior (warn-and-continue default, halt, retry-once) + includeTimings; proactive: true — must fire at session start to coordinate other proactive modules; target: tpm (TPM-only orchestration); custom steps supported by adding kv-entries with TPM-interpretable descriptions.
- [x] **tool.conversational-settings** — Natural-language settings-edit detector for TPM; watches user turns for phrases like "turn off database access" / "raise the regression-scan flag threshold to 3", fuzzy-matches against loaded module settings, and surfaces the exact panel edit needed; configurable enableDetection + triggerPhrases + applicationMode (propose default, apply, ask) + requireConfirmationFor (all/secrets/allowlists/modes category tags) + fuzzyMatchThreshold (default 70); not proactive — fires on user-turn parsing; today's default propose surfaces the Modules tab path for manual application, with apply falling back to propose until the future settings-write API lands.
- [x] **tool.setup-walkthrough** — Agent-driven first-time-setup playbook for new Nomeda users; proactive — detects fresh-install state at session start and offers a guided walkthrough of five default stages (obsidian / atlassian / modules-default-set / scm-widgets / first-session); configurable autoOfferOnFreshInstall + stages (keyValue with optionalEnabled per-stage) + freshInstallSignal (no-prior-handoff default, empty-feedback-log, always-offer, manual-only) + paceMode (interactive default, linear, self-paced) + completionTracking; target: tpm; persists per-stage completion in workspaceState to suppress re-offers.
- [x] **tool.docker** — Capability-allowlist module for docker and docker-compose CLI invocations parallel in shape to tool.dotnet-suite and tool.npm-suite; configurable allowedCommands (multiSelect string + keywords file with 16 seeded entries covering ps/images/logs/inspect/exec/build/pull/push/run/stop/rm/rmi plus compose up/down/logs/ps); default empty allowlist refuses every docker invocation; always-applied file guardrails for Dockerfile, docker-compose.yml, .dockerignore (flag before changing); standard module-disabled vs allowlist-empty refusal split.
- [x] **tool.open-wsl-repo** — TPM quick-navigation helper for WSL-native repos; configurable searchRoots (default ~/projects, ~/src, ~/code, ~/workspace) + fuzzyMatch + openCommand (code default, code-insiders, cursor, etc.) + triggerPhrases + onMultipleMatches (ask default, first, refuse); not proactive — fires on trigger-phrase detection; surfaces the open command for the user to run, never executes; target: tpm.
- [x] **tool.playwright** — QA-only module that writes Playwright test specs from testing procedures produced by tool.ac-to-testing; configurable specsDir (default ~/.nomeda/tests, persists outside the work repo) + configTemplate (base-url-env default, hardcoded-localhost, minimal) + autoOfferOnProcedures + specPerProcedure (one spec per TP vs consolidated per ticket) + includeSetupTeardown; not proactive — fires after procedures exist; per-ticket subdir keyed by ticket id; shared playwright.config.ts at specsDir root; tool.edge-auth-context (not yet built) will fold in for Azure AD auth.
- [x] **tool.ssh-access** — Per-host allowlist module for SSH-based remote commands parallel in shape to tool.git/tool.dotnet-suite/tool.docker; configurable allowedHosts (keyValue with optionalEnabled per-host) + allowedCommandPatterns (default covers read-only inspection like ls/pwd/ps/df/free/uptime/journalctl/systemctl status/docker ps/docker logs/tail/cat/less/head) + requireKnownHosts (default on — refuses unless host in ~/.ssh/known_hosts) + onCommandRefusal (refuse default, log-only, ask) + timeoutSeconds (default 30); default empty allowedHosts refuses every SSH invocation; always-applied protections forbid piping credentials, setting StrictHostKeyChecking=no, and reading ~/.ssh/known_hosts content directly.
- [x] **tool.core-allocation** — Codifies SWE core allocation (performance vs efficiency) plus model-by-difficulty assignment; configurable performanceCores (default 2) + efficiencyCores (default 1) + modelByDifficulty (keyValue with seeded low→haiku / medium→sonnet / high→opus) + highPriorityMode (all-hands default / perf-only / normal) + announceDispatchPlan; not proactive — applies on-demand at dispatch time; target: tpm; performance cores always dispatched first, efficiency cores handle side tasks when perf cores are busy; defers from inline TPM core behavior when enabled.
- [x] **tool.subagent-coordination** — Codifies file-ownership statements in parallel SWE dispatches + lens auto-merge when cores are scarce; configurable requireFileOwnership + allowSharedFileWrites (default off for collision safety) + lensAutoMergeBelowCores (default threshold 3 — fewer cores triggers lens merging) + coordinationStyle (split-by-file default, split-by-module, split-by-feature) + reportCollisions; not proactive — applies on-demand at parallel dispatch; target: tpm; SWE stays in declared ownership scope; defers from inline TPM core behavior when enabled.
